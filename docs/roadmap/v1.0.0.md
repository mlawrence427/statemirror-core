# StateMirror Core v1.0.0 Roadmap

Goal: stabilize StateMirror Core as a small, schema-agnostic evidence preservation runtime.

This is a stability checklist, not a feature roadmap.

## Scope

* Stable capture semantics
* Stable retrieval semantics
* Stable integrity semantics
* Stable Evidence Lane posture
* Stable boundaries
* Stable examples
* Stable failure-mode documentation
* Production-readiness guidance

## Non-goals

* No v0.4.0 feature expansion
* No policy engine
* No workflow engine
* No enforcement layer
* No observability replacement
* No hosted-service assumptions
* No AI analysis
* No dashboard or alerting system

## Release Posture

v1.0.0 should make the current core dependable, documented, and boring.

StateMirror should remain self-hosted, schema-agnostic, and explicit about its boundary.

Evidence Lanes remain optional canonical shapes, not required schemas.

## Success Criteria

A new engineer should be able to answer:

* What does StateMirror preserve?
* What does StateMirror verify?
* What does StateMirror not do?
* When would I use it?
* When would I not use it?

## Boundary Checks

Before v1.0.0, documentation and examples should make clear that:

* StateMirror preserves submitted decision evidence.
* StateMirror verification checks preserved evidence integrity only.
* StateMirror does not prove decision correctness.
* StateMirror does not prove upstream truth.
* StateMirror does not validate policy correctness.
* StateMirror does not decide, enforce, execute workflows, replace observability, or operate as a hosted service.
* Custom evidence schemas remain first-class.
