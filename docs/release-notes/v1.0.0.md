# StateMirror Core v1.0.0 Release Notes

Stability Release

StateMirror = decision-time evidence ledger for application systems

v1.0.0 stabilizes the existing model. It does not expand product scope.

Canonical model:

```txt
Application -> Decision -> Evidence -> StateMirror -> Verification
```

## Highlights

- Stable evidence preservation semantics
- Stable retrieval semantics
- Stable integrity semantics
- Stable Evidence Lane posture
- Stable boundaries
- Production guidance
- API and CLI documentation for existing behavior
- Examples and failure-mode documentation

## Stable Semantics

StateMirror preserves submitted decision evidence as immutable snapshots.

Verification checks structural and cryptographic integrity only:

- payload hash
- chain hash
- previous-chain linkage
- sequence continuity
- missing or malformed preserved records where applicable

Verification does not prove:

- decision correctness
- policy correctness
- upstream truth
- side-effect execution
- compliance status

## Evidence Lane Posture

PlanEvidence, DenialEvidence, and ExpiryEvidence remain optional canonical shapes.

They are examples for common evidence patterns. They are not required schemas, not enforcement systems, and not policy engines.

Custom evidence remains first-class.

## Boundaries

No feature expansion.

StateMirror Core is not:

- a workflow engine
- a policy engine
- an observability system
- a hosted service
- an authorization system
- an enforcement layer
- a dashboard or alerting product

The application decides and executes outcomes.

StateMirror preserves evidence.
